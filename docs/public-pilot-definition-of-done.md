# Definition of Done следующего публичного пилота InfoQuest

**Версия:** 1.0

**Дата:** 10 августа 2026 года

**Объём пилота:** RU/RO, один доступный модуль `operator-call`, восемь этапов, профиль, прогресс, админ-панель и Chrono для разрешённых ролей.

Публичный пилот получает решение **GO** только тогда, когда выполнены все обязательные критерии ниже и для каждого приложено проверяемое доказательство. Формулировка «работает у разработчика» доказательством не считается.

## 1. Release gate

| ID | Обязательный критерий | Доказательство | Статус |
|---|---|---|---|
| G-01 | Старый раскрытый Google OAuth Client Secret отозван, новый secret работает на production | Скриншот/запись Google Cloud без значения secret + успешный вход на production | ⬜ |
| G-02 | Последний commit развёрнут на staging и production, deployment имеет статус Ready | Ссылки на два deployment и commit SHA | ⬜ |
| G-03 | GitHub Actions полностью зелёный: install, lint, typecheck, unit, build и Playwright | Ссылка на успешный workflow | ⬜ |
| G-04 | Авторизованный E2E проходит для RU и RO: login-сессия, профиль, модуль, сохранение этапа и повторная загрузка | Playwright report | ⬜ |
| G-05 | Privacy/terms проверены специалистом; определены правила участия несовершеннолетних и приватный контакт по данным | Дата, имя проверяющего, решение «можно запускать» или письменные условия | ⬜ |
| G-06 | В AI-провайдере установлен денежный hard cap и уведомление; подтверждены правила хранения и субобработчики | Скриншот настроек без ключей + письменный ответ/условия провайдера | ⬜ |
| G-07 | Все учебные видео имеют синхронные RU/RO-субтитры и проверены без звука | WebVTT-файлы, `<track kind="captions">`, ручной чек | ⬜ |
| G-08 | Пройден внутренний pre-pilot минимум с 5 пользователями каждого языка и закрыты все критические проблемы | Краткий протокол тестирования и список закрытых дефектов | ⬜ |

Если хотя бы один пункт G-01–G-08 не выполнен, публичный запуск получает **NO-GO**. Допускается только закрытая демонстрация команды без привлечения новых несовершеннолетних пользователей и без сбора новых данных.

## 2. Функциональная готовность

- [ ] На `/ru` и `/ro` доступен только `operator-call`; остальные семь модулей явно показывают «Скоро» и не выглядят кликабельными.
- [ ] Новый пользователь после Google-входа получает роль `user`, видит профиль и может открыть только первый модуль.
- [ ] Роли `student`, `teacher`, `administrator` открывают Chrono; `user` и `blocked` получают понятный отказ.
- [ ] Все восемь этапов проходят последовательно на RU и RO без ручного изменения данных.
- [ ] После каждого этапа обновляются Supabase, профиль, XP, бейдж и щит; состояние сохраняется после выхода и повторного входа.
- [ ] Нельзя завершить закрытый этап раньше предыдущего через UI или прямой RPC.
- [ ] Финальная игра полностью проходит на обоих языках минимум два раза подряд.
- [ ] Основной CTA вошедшего пользователя ведёт к первому незавершённому этапу или профилю, а не возвращает на login.
- [ ] Ошибки Supabase/AI показывают понятное сообщение и возможность повторить действие без потери уже сохранённого прогресса.

## 3. Безопасность и данные

- [ ] В Git-истории, Vercel logs, браузерном bundle и документации нет действующих OAuth/API secrets.
- [ ] Production/Preview используют разные проверенные переменные окружения; обязательные env завершают сборку с ошибкой при отсутствии.
- [ ] RLS-негативные тесты подтверждают: пользователь не читает и не изменяет чужие профиль, роль и прогресс.
- [ ] Администраторские аккаунты подтверждены владельцами и защищены MFA/AAL2.
- [ ] Роль `blocked`, блокировка email/account и IP действуют на страницы, RPC прогресса и прямой `/api/ai`.
- [ ] AI route проверяет сессию, роль, явное согласие, лимит размера, MIME/signature и длительность аудио до отправки провайдеру.
- [ ] Работают 3 аудиоанализа в день, дневной/месячный лимит пользователя, общий проектный лимит, конкурентный lock и timeout.
- [ ] Текст, аудио, транскрипция и AI-ответ не сохраняются InfoQuest без отдельного согласия; это соответствует production logs и настройкам провайдера.
- [ ] Подготовлен контакт и короткий порядок действий при утечке, злоупотреблении, ошибочной блокировке или неприемлемом AI-ответе.

## 4. Доступность и контент

- [ ] Весь модуль проходится клавиатурой без мыши; фокус всегда видим и не теряется после результата или модального окна.
- [ ] Таймеры можно поставить на паузу; отсутствие цвета не мешает понять выбор, ошибку и правильный ответ.
- [ ] Проверены NVDA + Chrome или эквивалентный screen reader: заголовки, кнопки, live-status и результаты понятны.
- [ ] Typewriter учитывает reduced motion и позволяет сразу показать полный текст.
- [ ] Видео имеют субтитры, понятный заголовок и управление с клавиатуры.
- [ ] RU/RO не содержат временных английских подписей `Intro`, `Language`, `Close`, `HP` в пользовательском интерфейсе.
- [ ] Учитель/редактор проверил факты, тон, возрастную уместность и одинаковый смысл RU/RO-контента.
- [ ] AI-ответ явно называется вероятностным анализом, не обвиняет конкретного человека и предлагает проверку через официальный канал.

## 5. Устройства и производительность

- [ ] Проверены минимум один Android-телефон, один iPhone или iPad и один ноутбук.
- [ ] Проверены ширины 320, 375, 768 и 1280 px: нет горизонтального скролла, перекрытий и недоступных кнопок.
- [ ] Первый экран, модуль и профиль работают на ограниченной мобильной сети; загрузка видео не блокирует основной интерфейс.
- [ ] Все MP4 воспроизводятся на целевых браузерах; визуальное качество сжатых файлов принято командой.
- [ ] Ошибка/обрыв сети во время сохранения или AI-запроса не приводит к ложному статусу завершения.

## 6. Наблюдаемость и проведение пилота

- [ ] Назначены ответственные за product, технические инциденты, данные/приватность и работу с участниками.
- [ ] Определены дата, длительность, аудитория, максимальное число участников и способ получения согласия.
- [ ] Есть dashboard/журнал для ошибок входа, ошибок RPC, отказов AI и достижения квот без записи содержимого пользовательских сообщений.
- [ ] Проверено уведомление при достижении 80% AI-бюджета и автоматическая остановка при hard cap.
- [ ] Подготовлен rollback: известен предыдущий рабочий deployment и человек, который может вернуть его не более чем за 15 минут.
- [ ] Подготовлен канал обратной связи RU/RO и короткая анкета без лишних персональных данных.
- [ ] После пилота назначен срок разбора результатов и удаления/анонимизации временных списков участников и диагностических данных.

## 7. Условия немедленной остановки

Пилот останавливается, если обнаружено хотя бы одно событие:

- доступ к чужому профилю, роли или прогрессу;
- раскрытие действующего secret или персональных данных;
- обход роли `blocked` или AI-квоты;
- массовая невозможность входа/сохранения прогресса;
- неприемлемый или опасный AI-ответ без доступного способа отключить Chrono;
- превышение согласованного AI-бюджета;
- требование специалиста по данным или организатора прекратить обработку.
